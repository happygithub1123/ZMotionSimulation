# ZMotionSDK 项目结构与运行指南

本说明依据当前本机源码编写。项目位置：`G:\C# ZMotionSDK\ZMotionSDK-GitHub-20261114`。此前已完成完整解决方案编译验证，但尚未连接控制器验证硬件功能。

## 1. 先分清：解决方案、项目、文件

| 对象 | 在这里的含义 | 怎么操作 |
| --- | --- | --- |
| 解决方案 `.sln` | 把几个项目组织在一起的入口 | 用 Visual Studio 打开根目录的 `ZMotionSDK.sln` |
| 项目 `.csproj` | 定义编译方式、依赖、目标框架和输出类型 | 一般在解决方案中管理，不单独双击里面的源码运行 |
| `ZMotionSDK` 项目 | 运动控制接口类库，输出 `ZMotionSDK.dll` | 由应用引用，不能作为有窗口的软件单独启动 |
| `ZMotionTest` 项目 | 调用 SDK 的 Windows WPF 调试应用，输出 `ZMotionTest.exe` | 设为启动项目后按 F5 或 Ctrl+F5 |
| `.cs` 文件 | C# 类型、逻辑、命令或数据模型 | 加入项目后统一编译，通常不能单独运行 |
| `.xaml` 文件 | 窗口、页面、控件的布局和绑定 | 用设计器或文本编辑，运行应用后显示 |
| `.xaml.cs` 文件 | 同名界面的代码，通常负责初始化与绑定 | 和同名 XAML 配合使用 |
| 原生 `.dll` | 厂家提供的本机通信组件 | 位数必须匹配，放到应用可找到的位置 |
| `.md` 文件 | 文档 | 阅读使用，不参与程序运行 |

特别注意：仓库有两个同名解决方案。根目录 `ZMotionSDK.sln` 包含 SDK 和测试程序；`src/ZMotionSDK/ZMotionSDK.sln` 只有 SDK。要运行带界面的完整程序，打开根目录那个。

## 2. 在 Visual Studio 中运行

1. 文件 → 打开 → 项目/解决方案，选择根目录 `ZMotionSDK.sln`。
2. 右侧确认有 `ZMotionSDK`、`ZMotionTest` 两个项目，而且没有“已卸载”。
3. 右键 `ZMotionTest` → 设为启动项目。它是带窗口的应用。
4. 顶部配置选择 `Debug`、平台选择 `x64`。本仓库两个厂家 DLL 已检查为 x64。
5. 生成 → 生成解决方案，或按 Ctrl+Shift+B。NuGet 依赖应成功还原。
6. **补齐原生 DLL**：把 `src/ZMotionSDK/dll/` 中的 `zauxdll.dll`、`zmotion.dll` 复制到 `tests/ZMotionTest/bin/x64/Debug/net8.0-windows/`，与 `ZMotionTest.exe` 同一层。当前项目不会自动复制这两个文件。
7. 按 F5 启动并调试；只想打开程序、不进入调试，可按 Ctrl+F5。
8. 如有异常，查看“输出”和“错误列表”。调试时双击错误可以跳到对应源码。

F9 在可执行语句处设置或取消断点，F10 逐过程，F11 进入方法。设置断点时注意控制器可能仍在执行已经收到的运动指令，暂停电脑代码不等于停止硬件。

若使用 `Any CPU` 构建，当前输出目录通常是 `tests/ZMotionTest/bin/Debug/net8.0-windows/`，与 x64 配置的目录不同。复制 DLL 时必须对应实际启动的 EXE 所在目录。

## 3. 不通过 Visual Studio 运行

以下命令在 PowerShell 执行。这里提供命令供你手动使用，未在编写本说明时启动硬件程序。

```powershell
Set-Location -LiteralPath 'G:\C# ZMotionSDK\ZMotionSDK-GitHub-20261114'
& 'C:\Program Files\dotnet\dotnet.exe' build '.\ZMotionSDK.sln' -c Debug -p:Platform=x64
```

确认构建成功后，复制两个 DLL，再启动 EXE：

```powershell
$appOutput = 'G:\C# ZMotionSDK\ZMotionSDK-GitHub-20261114\tests\ZMotionTest\bin\x64\Debug\net8.0-windows'
Copy-Item -LiteralPath '.\src\ZMotionSDK\dll\zauxdll.dll' -Destination $appOutput
Copy-Item -LiteralPath '.\src\ZMotionSDK\dll\zmotion.dll' -Destination $appOutput
& (Join-Path $appOutput 'ZMotionTest.exe')
```

第一次生成新配置前输出目录可能还不存在，先构建再复制。以后清理、切换配置或重新发布，可能需要重新复制。

要在同一台电脑重复运行，进入对应输出文件夹双击 `ZMotionTest.exe` 即可。不要只把一个 EXE 拿到另一台电脑；应用还依赖同目录程序集、配置、厂家 DLL，以及 .NET 8 Windows Desktop Runtime（框架依赖部署时）。

## 4. 软件界面怎么操作

建议顺序：连接管理 → 轴状态监控 → 参数读取 → 单轴控制 → IO → 缓存运动。涉及使能、运动和输出的操作，应按现场接线与控制器参数确认，示例默认值不代表你的设备配置。

### 4.1 连接管理

- 当前实际代码提供的是 IP 网络连接入口。默认 IP 是 `192.168.0.11`，构造函数设置的默认超时为 `5000` 毫秒。
- 填写控制器实际 IP 和超时后点击连接，确认界面显示已连接。
- IP 默认值只是代码初始值，需要与你的控制器匹配。电脑与控制器的地址、掩码和网络路径也应匹配。
- 完成调试后回连接页断开连接。
- README 提到串口、自动重连，但当前 `ConnectionViewModel` 仅实现显式网络连接与断开，不要把文档描述当作已经具备的界面功能。

### 4.2 轴状态监控

- 设置要查看的轴数量。代码默认 8 轴，刷新间隔默认 100 毫秒；这些不是自动检测结果。
- 可以开始监控、停止监控或单次刷新。
- 查看规划位置 DPOS、反馈位置 MPOS、速度、运行状态等。
- 优先使用这个页面确认读数，之后再做会改变硬件状态的操作。

### 4.3 参数测试

- 选择正确轴号及可读参数，点击读取。
- 可批量读取常用参数，或使用预设快捷选择。
- 写参数会改变控制器参数。先记录原值，理解参数含义后再写入。
- 轴号、Units、Speed、Accel、Decel 等应按实际机构配置，不能直接把 README 中的示例值作为现场参数。

### 4.4 轴运动控制

- 选择实际轴号，先读取当前参数和状态。
- 按轴类型设置脉冲当量、速度、加减速度、限位等，再操作使能。
- 相对运动：相对当前位置移动给定距离；绝对运动：移动到给定坐标。
- 点动：正向或负向连续运行，应明确停止按钮位置；不要默认它是松开鼠标自动停止的行为。
- 回零：根据原点开关、方向和驱动器方式选择模式，不能只凭按钮名称决定。
- 页面的暂停、恢复、停止和“急停”由软件命令实现，不能替代设备独立硬件急停。
- 总线初始化、清报警、在线命令是高级操作，会作用于控制器或驱动器，按对应设备配置使用。

### 4.5 IO 控制

- DI 为输入，主要用于读取传感器、按钮状态；DO 为输出，写入后可能驱动外设。
- 单个 IO 区域可刷新输入、输出，输出状态变化会调用写 DO 的逻辑。
- Modbus 与批量 IO 区域按起止索引读取/写入。先核对索引范围。
- 协议区域用中文名称表示信号，名称与真实地址的对应关系在 `Protocol/DIProtocol.cs` 和 `Protocol/DOProtocol.cs` 中。
- 当前 IO 页面构造时启动 300 毫秒轮询，轮询方法没有完整的未连接保护与异常兜底。应连接成功后再打开此页；无设备时不要用它当模拟界面。
- 最近新增的本地 `DataStatusControl` 显示名称、地址和 ON/OFF 状态；输出项显示“切换”，输入项隐藏该按钮。

### 4.6 运动缓存

- 选择轴，查看剩余缓存、移动标记、剩余距离等。
- 可添加单次移动、序列移动、缓存 IO、延时和自定义命令。
- **“添加移动”会立即向控制器提交命令，并非只保存在电脑的列表里等待另一个开始按钮。** 队列日志用于显示提交记录。
- 先用简单单次指令确认行为，再组合运动序列。停止、清空缓存等按钮会影响真实运动。

### 4.7 没有控制器时能做什么

可以打开工程、看源码、编译、查看默认连接页面。当前代码没有完整模拟器。不能据“界面能打开”断言 IO、回零、运动、EtherCAT 等功能已验证。

## 10. 从按钮追到代码的方法

以连接按钮为例：

```text
App.xaml（启动 MainWindow）
  → MainWindow.xaml.cs（默认打开 ConnectionPage）
  → ConnectionPage.xaml（按钮绑定 ConnectCommand）
  → ConnectionViewModel.Connect()
  → ZMotionManager.Connect()
  → ZMotion.Open()
  → zmcaux.ZAux_FastOpen()
  → zauxdll.dll / zmotion.dll
  → 控制器
```

CommunityToolkit.Mvvm 会根据 `[RelayCommand]` 自动生成 `ConnectCommand`，根据 `[ObservableProperty]` 自动生成可绑定属性。所以搜索不到手写 ConnectCommand 是正常的，不要去 obj 中改生成代码。

日常修改位置：

- 改按钮、标题、排列：对应页面 XAML。
- 改按钮行为：对应 ViewModel。
- 改默认 IP：ConnectionViewModel 构造函数及初始字段。
- 改 IO 名称和地址：Protocol 下两个协议文件。
- 改统一设备调用：ZMotionManager。
- 增加 SDK 能力：ZMotion 的相应 partial 源码文件；先确认厂家 API。
- 改状态卡片外观：DataStatusControl.xaml。
- 改全局主题：App.xaml。

## 11. 当前常见故障与处理

| 现象 | 检查位置与处理 |
| --- | --- |
| 项目“已卸载” | 右键重新加载，先看具体错误。仅登录 GitHub 不能补齐 SDK 或本机环境。 |
| 找不到 Microsoft.NET.Sdk | 本机已安装 .NET 8.0.400；此前已补入用户 PATH 的 `C:\Program Files\dotnet`。旧 VS 进程不一定取得新环境，重开 VS。 |
| 找不到 WPFProject.Share | 当前已由本地模型和控件替代，确认打开的是本目录最新项目，接受重新加载并还原依赖。 |
| DllNotFoundException / 找不到 zauxdll.dll | 将厂家两个 DLL 放到实际 EXE 所在目录；若已存在，还需排查它们依赖的本机组件。 |
| BadImageFormatException / 格式不正确 | 原生 DLL 与进程位数不匹配，当前仓库应使用 x64。 |
| 连接失败 | 核对实际 IP、网络、控制器上电状态；看返回信息。不能只凭默认 IP 断定设备故障。 |
| 点击 IO 页面后异常 | 先确认设备已连接；当前轮询的连接保护和异常处理不完整，需要单独改进。 |
| 只能看到 SDK，找不到测试窗口 | 打开根目录解决方案，将 ZMotionTest 设为启动项目。 |
| 类库无法直接启动 | 启动项目选成了 ZMotionSDK，改选 ZMotionTest。 |
| 编译有很多警告 | 上次完整编译为 0 错误、150 警告，主要涉及 XML 注释和空值检查；警告与成功进行硬件测试是不同的概念。 |
